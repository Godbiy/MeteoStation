# ЧАСТИНА 0 — ЯК ВЗАГАЛІ ЦЕ ПРОГРАМУВАТИ (читай спочатку)

## Що таке мікроконтролер простими словами

Це маленький комп'ютер на одному чіпі. Всередині є:
- **Flash** (~32 КБ) — тут зберігається твій код (як SSD)
- **RAM** (2 КБ) — тут живуть змінні під час роботи (як оперативна пам'ять)
- **EEPROM** (1 КБ) — пам'ять яка не стирається при вимкненні (як флешка)
- **Піни** — ніжки мікросхеми, ними ти спілкуєшся з залізом

Після того як прошив — МК одразу починає виконувати `main()` і крутиться там вічно.
Немає операційної системи. Немає файлів. Тільки твій код і залізо.

---

## Як виглядає типова програма

```c
#include <avr/io.h>        // регістри PIN/DDR/PORT і всі PB0, PD3 тощо
#include <util/delay.h>    // _delay_ms()
#include <avr/interrupt.h> // sei(), cli(), ISR()

int main(void)
{
    // 1. ІНІЦІАЛІЗАЦІЯ — виконується один раз
    DDRB |= (1 << PB5);    // PB5 = вихід (LED на Arduino = D13)

    // 2. ГОЛОВНИЙ ЦИКЛ — крутиться вічно
    while (1) {
        PORTB |=  (1 << PB5);  // HIGH — LED увімкнено
        _delay_ms(500);
        PORTB &= ~(1 << PB5);  // LOW  — LED вимкнено
        _delay_ms(500);
    }

    return 0;  // ніколи не досягається, але компілятор хоче бачити
}
```

**Правило:** спочатку ініціалізуй все (піни, UART, переривання), потім `sei()`, потім головний цикл.

## Як думати про залізо

Уяви що піn — це вимикач або лампочка:
- **Вихід (OUTPUT)** = лампочка. Ти кажеш МК: "постав тут HIGH або LOW"
- **Вхід (INPUT)** = вимикач. Ти питаєш МК: "що зараз на цьому піні?"

Підтяжка (pull-up) — це резистор всередині МК який тягне піn до VCC.
Потрібна щоб піn не "плавав" коли нічого не підключено.

```
З pull-up:
  VCC ──[50кОм]──┬── піn МК
                 │
  кнопка ────────┴── GND

  Кнопка відпущена → піn читає HIGH (тягнеться до VCC)
  Кнопка натиснута → піn читає LOW  (з'єднано з GND)
```

## Що таке стейт-машина (State Machine)

Це спосіб організувати складну логіку. Замість купи `if/else` — список станів і переходи між ними.

```c
typedef enum {
    СТАН_А,
    СТАН_Б,
    СТАН_В
} стан_t;

стан_t стан = СТАН_А;

while (1) {
    switch (стан) {
    case СТАН_А:
        // робимо щось
        стан = СТАН_Б;  // переходимо далі
        break;
    case СТАН_Б:
        // робимо інше
        стан = СТАН_В;
        break;
    case СТАН_В:
        // робимо третє
        стан = СТАН_А;  // повертаємось на початок
        break;
    }
}
```

В нашому проекті стейт-машина: `SM_GSM_INIT → SM_SLEEP_SAMPLE → SM_READ_VBAT → SM_HTTP_POST → SM_SLEEP_SAMPLE → ...`

## Що таке переривання (Interrupt)

Уяви що ти слухаєш музику і раптом дзвонить телефон.
Ти ставиш музику на паузу, відповідаєш, кладеш слухавку — і продовжуєш слухати.

Переривання — те саме. МК виконує код, і раптом щось відбулось на піні (або WDT спрацював) → МК "ставить код на паузу", виконує `ISR()` → повертається до того місця де зупинився.

```c
// Переривання спрацьовує АВТОМАТИЧНО при зміні PD2
ISR(PCINT2_vect)
{
    g_wind_pulses++;  // просто рахуємо, нічого складного
}

// В main() тим часом може спати або робити інше
// При кожному імпульсі ISR виконається автоматично
```

**Важливо в ISR:**
- Роби мінімум роботи — тільки встанови прапорець або збільш лічильник
- Не викликай `_delay_ms()` і не пиши в UART — занадто повільно
- Змінні що змінюються в ISR — `volatile`

## Типові помилки початківців

### ❌ Забув зробити DDR перед PORT
```c
PORTB |= (1 << PB3);   // НЕПРАВИЛЬНО — ще не сказали що це вихід
// результат: увімкнеться pull-up, але не HIGH вихід
```
```c
DDRB  |= (1 << PB3);   // ПРАВИЛЬНО: спочатку вихід
PORTB |= (1 << PB3);   // потім HIGH
```

### ❌ Забув = замість |= (стирає всі інші біти)
```c
DDRB = (1 << PB3);    // ПОГАНО — скидає всі інші біти DDRB в 0!
DDRB |= (1 << PB3);   // ДОБРЕ — тільки встановлює PB3, решта без змін
```

### ❌ Не оголосив volatile для ISR змінної
```c
uint16_t g_pulses = 0;           // ПОГАНО — компілятор може закешувати
volatile uint16_t g_pulses = 0;  // ДОБРЕ
```

### ❌ Забув sei()
```c
PCICR |= (1 << PCIE2);   // налаштував переривання
// забув sei()           // але переривання не спрацюють
```
```c
PCICR |= (1 << PCIE2);
sei();                   // тепер переривання активні
```

### ❌ Читає PINext замість PINx
```c
if (PORTB & (1 << PB0))  // НЕПРАВИЛЬНО — PORT, а не PIN
if (PINB  & (1 << PB0))  // ПРАВИЛЬНО  — читаємо стан піна
```

### ❌ F_CPU не визначено до delay
```c
#include <util/delay.h>   // НЕПРАВИЛЬНО — delay не знає частоту
#define F_CPU 1000000UL
```
```c
#define F_CPU 1000000UL   // ПРАВИЛЬНО: спочатку визначаємо
#include <util/delay.h>   // потім підключаємо
// або через config.h який включається першим
```

## Як дебажити без дисплея

У нас немає дисплея, але є Software UART на PC1. Правила:

```c
dbg_puts_P(PSTR("BOOT_OK"));     // рядок з FLASH (економить RAM)
dbg_puts("hello");               // рядок з RAM
dbg_putu16(1234);                // число uint16
dbg_putc('A');                   // один символ
```

**Підключення:** PC1 (фізичний пін) → USB-UART адаптер RX → комп'ютер.
Швидкість: 4800 бод, 8N1.

Стратегія дебагу:
1. Після кожного кроку ініціалізації — `dbg_puts_P(PSTR("INIT_OK"))`
2. Перед і після підозрілого місця — виводити значення змінних
3. В ISR — **не виводити** (занадто повільно, зламає тайминги)

## 1. Три головних регістри для кожного порту

Кожен порт (B, C, D) має три регістри:

| Регістр | Що робить |
|---------|-----------|
| `DDRx`  | Direction — 1=вихід, 0=вхід |
| `PORTx` | Output — якщо вихід: 1=HIGH, 0=LOW; якщо вхід: 1=pull-up увімкнено |
| `PINx`  | Input — читаємо стан піна (тільки читання) |

де `x` = B, C або D.

## 2. Налаштування піна

### Вихід (OUTPUT)
```c
// Зробити PD3 виходом
DDRD |= (1 << PD3);

// Встановити HIGH
PORTD |= (1 << PD3);

// Встановити LOW
PORTD &= ~(1 << PD3);
```
**Приклад з проекту:** MOSFET флюгера на PD3
```c
DDRD  |=  (1 << PIN_VANE_ON);   // PD3 = вихід
PORTD &= ~(1 << PIN_VANE_ON);   // LOW (вимкнено)
// ...пізніше вмикаємо:
PORTD |= (1 << PIN_VANE_ON);    // HIGH (увімкнено)
```

---

### Вхід БЕЗ підтяжки (floating input)
```c
DDRD &= ~(1 << PD5);    // PD5 = вхід
PORTD &= ~(1 << PD5);   // pull-up вимкнено — піn "плаває"
```
⚠️ Не рекомендується — піn може читати випадкові значення.

---

### Вхід з PULL-UP (підтяжка до VCC)
```c
DDRB  &= ~(1 << PB1);   // PB1 = вхід
PORTB |=  (1 << PB1);   // pull-up увімкнено (~50кОм до VCC)
```
Якщо нічого не підключено — читається 1 (HIGH).
Якщо підключено до GND — читається 0 (LOW).

**Приклад з проекту:** піни флюгера
```c
DDRB  &= ~((1 << PB0) | (1 << PB1) | (1 << PB2));  // входи
PORTB |=  ((1 << PB0) | (1 << PB1) | (1 << PB2));  // pull-up
```

---

### PULL-DOWN (підтяжка до GND)
ATmega328P **не має** апаратного pull-down!
Якщо треба pull-down — паяти зовнішній резистор 10кОм між піном і GND.

---

## 3. Читання стану піна

```c
// Якщо PB0 = HIGH — виконати щось
if (PINB & (1 << PB0)) {
    // піn HIGH
}

// Якщо PD2 = LOW — виконати щось
if (!(PIND & (1 << PD2))) {
    // піn LOW
}
```
**Приклад з проекту:** читання 8 пінів флюгера в один байт
```c
uint8_t vane = 0;
if (PINB & (1 << PB0)) vane |= (1 << 0);  // біт 0
if (PINB & (1 << PB1)) vane |= (1 << 1);  // біт 1
if (PINB & (1 << PB2)) vane |= (1 << 2);  // біт 2
// ... і так далі
// результат: vane = 0b00000101 якщо PB0 і PB2 = HIGH
```

## 4. Оператори для роботи з бітами

| Операція | Синтаксис | Що робить |
|----------|-----------|-----------|
| Встановити біт | `REG \|= (1 << N)` | ставить N-й біт в 1 |
| Скинути біт | `REG &= ~(1 << N)` | ставить N-й біт в 0 |
| Перевірити біт | `REG & (1 << N)` | != 0 якщо біт = 1 |
| Інвертувати | `REG ^= (1 << N)` | міняє на протилежне |

```c
// Встановити кілька бітів одразу через |
PORTB |= (1 << PB0) | (1 << PB1) | (1 << PB3);

// Скинути кілька бітів одразу
PORTB &= ~((1 << PB0) | (1 << PB1) | (1 << PB3));
```

## 5. #define для пінів (як в config.h)

Правильний стиль — давати пінам імена через `#define`:
```c
// config.h
#define PIN_VANE_ON    PD3
#define PIN_WIND_SPEED PD4
#define PIN_DBG_TX     PC1

// sensor.c — читаємо по імені, не по номеру
DDRD |= (1 << PIN_VANE_ON);       // зрозуміло що це MOSFET
PORTD |= (1 << PIN_VANE_ON);      // вмикаємо флюгер
```
Не пиши `(1 << PD3)` прямо в коді — якщо переробиш PCB і переключиш піn, міняєш тільки в одному місці в config.h.

## 7. Переривання (Interrupts)

### Глобальне увімкнення/вимкнення
```c
sei();   // увімкнути всі переривання (Set Enable Interrupts)
cli();   // вимкнути всі переривання (CLear Interrupts)
```

### Pin Change Interrupt (PCINT) — "спрацює коли піn змінився"
```c
// Вмикаємо переривання на PD2 (PCINT18, група PCIE2)
PCICR  |= (1 << PCIE2);    // вмикаємо групу PORTD
PCMSK2 |= (1 << PCINT18);  // конкретно PD2

// Обробник переривання
ISR(PCINT2_vect)
{
    if (PIND & (1 << PD2))   // перевіряємо — це зростаючий фронт?
        g_wind_pulses++;
}
```
**Приклад з проекту:** лічильник імпульсів анемометра на PD4
```c
ISR(PCINT2_vect)
{
    if (PIND & (1 << PIN_WIND_SPEED))
        g_wind_pulses++;
}
```

### Змінні які змінюються в ISR — завжди `volatile`
```c
volatile uint16_t g_wind_pulses = 0;
//       ^^^^^^^^ обов'язково — інакше компілятор може оптимізувати і не читати з RAM
```

### Атомарне читання volatile змінної
```c
cli();
uint16_t pulses = g_wind_pulses;  // читаємо без переривань
g_wind_pulses = 0;
sei();
```

## 8. Типи даних (stdint.h)

| Тип | Розмір | Діапазон |
|-----|--------|----------|
| `uint8_t` | 1 байт | 0 … 255 |
| `int8_t` | 1 байт | -128 … 127 |
| `uint16_t` | 2 байти | 0 … 65535 |
| `int16_t` | 2 байти | -32768 … 32767 |

На AVR завжди використовуй ці типи — розмір гарантований.
Не пиши `int` або `long` — їх розмір залежить від платформи.

## 9. PROGMEM — рядки у флеш-пам'яті

RAM у ATmega328P всього 2 КБ. Рядки зберігати в FLASH:
```c
#include <avr/pgmspace.h>

// Вивести рядок з FLASH
dbg_puts_P(PSTR("BOOT_OK"));

// Якщо пишеш так — рядок їсть дорогоцінну RAM:
dbg_puts("BOOT_OK");   // ПОГАНО для AVR

// Так — рядок у FLASH, RAM не витрачається:
dbg_puts_P(PSTR("BOOT_OK"));   // ДОБРЕ
```

## 10. Упаковка даних в байт і розпаковка

**Пакуємо** (кілька значень → один байт):
```c
uint8_t vane = 0;
if (PINB & (1 << PB0)) vane |= (1 << 0);  // піn 0 → біт 0
if (PINB & (1 << PB1)) vane |= (1 << 1);  // піn 1 → біт 1
if (PINB & (1 << PB7)) vane |= (1 << 7);  // піn 7 → біт 7
// vane тепер містить стан 8 пінів в одному байті
```

**Розпаковуємо** (дістаємо конкретний біт):
```c
uint8_t vane = 0b11100111;

uint8_t bit3 = (vane >> 3) & 1;   // дістати біт 3 → 0 або 1
uint8_t bit0 = (vane >> 0) & 1;   // дістати біт 0 → 1
```

## 11. Піни PORTB / PORTC / PORTD у ATmega328P

```
PORTB: PB0..PB7
  PB0 = D8   PB4 = D12 (MISO)
  PB1 = D9   PB5 = D13 (SCK/LED)
  PB2 = D10  PB6 = XTAL1
  PB3 = D11  PB7 = XTAL2

PORTC: PC0..PC6  (7 пінів, PC7 не виведений)
  PC0 = A0   PC4 = A4 (SDA)
  PC1 = A1   PC5 = A5 (SCL)
  PC2 = A2   PC6 = RESET
  PC3 = A3

PORTD: PD0..PD7
  PD0 = D0 (RX)   PD4 = D4
  PD1 = D1 (TX)   PD5 = D5 (PWM)
  PD2 = D2 (INT0) PD6 = D6 (PWM)
  PD3 = D3 (INT1) PD7 = D7
```

## 13. Швидкий шаблон нового піна

```c
// 1. Додати в config.h:
#define PIN_MY_SENSOR  PB5

// 2. Ініціалізація (у відповідній init функції):
DDRB  &= ~(1 << PIN_MY_SENSOR);   // вхід
PORTB |=  (1 << PIN_MY_SENSOR);   // pull-up

// 3. Читання:
if (PINB & (1 << PIN_MY_SENSOR)) {
    // HIGH
}
```
